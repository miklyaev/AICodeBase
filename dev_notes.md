### 2026-11-08 — Синхронизация ссылок чата, результатов поиска и кода

**Область:** Frontend | QA

**Что изменилось:**
- Устранён неявный приоритет старых результатов поиска над новым ответом чата. Выбор ссылки в истории переключает правую панель на полный набор ссылок именно этого ответа; слева больше нет обрезки до трёх ссылок.
- Список, выбранная ссылка и фрагмент объединены в состояние с reducer. При переключении старый код сразу убирается; запоздалые ответы и ошибки загрузки фрагмента игнорируются. Ошибки открытия ссылок обрабатываются и показываются в интерфейсе.
- Сброс поиска восстанавливает ссылки последнего ответа, включая пустой результат, а не более раннего непустого ответа. Смена проекта очищает чат, ID беседы и результаты, инвалидируя запросы прежнего проекта; очистка индекса также убирает устаревшие ссылки.
- Monaco показывает исходные номера строк с учётом контекста; диапазоны сравниваются по файлу, начальной и конечной строкам. Подсветка применяется и при поздней загрузке редактора.

**Проверки:**
- Frontend Vitest: 49 тестов PASS, включая 8 новых регрессий состояния ссылок, гонок запросов, пустого ответа и номеров строк. TypeScript frontend (`--noEmit`) — PASS.
- Headless Edge/Playwright: 8 UI-сценариев PASS на настоящем React App с синтетическими API; проверены переключение поиска/чата, ссылки старого ответа, сброс к пустому ответу, смена проекта, гонки фрагментов и выбора проектов, обработка ошибки загрузки. Ошибок страницы и необработанных отклонений Promise нет. Команда: `node scripts/e2e/run-references.cjs`; отчёт: `reports/e2e/references.json`.
- Ограничение E2E: Monaco заменён локальным read-only textarea, поэтому его рендер, workers и визуальная подсветка в браузере не проверялись; вычисление исходных номеров строк покрыто unit-тестом.
- Пользовательские индексы не изменялись, запросы к LLM не выполнялись.

**Затронутые пути:**
- `apps/frontend/src/App.tsx`
- `apps/frontend/src/code-references.ts`
- `apps/frontend/src/__tests__/code-references.spec.ts`

### 2026-11-07 — Индексация пустых файлов и безопасная диагностика сбоев

**Область:** Backend | QA

**Что изменилось:**
- Исправлена причина остановки на пустом `backend/test-api.js`: пустое/пробельное содержимое и отдельные пустые окна не создают чанки. Сохраняются исходные номера строк и последовательные номера непустых чанков.
- `LlmService` отклоняет пустые элементы локально, не сдвигая соответствие входов/векторов; ошибки сохраняют только безопасный HTTP-код провайдера, без тела ответа и ключей.
- Ошибки чтения отдельного файла и HTTP 400/413/422 не прерывают обработку остальных файлов. При наличии ошибок проект остаётся `failed` с итоговым счётчиком и контекстом первого сбоя. Глобальные ошибки авторизации, сети, лимитов и хранилищ по-прежнему останавливают работу.
- Статус/SSE показывают относительный файл, этап и HTTP-код. Исходные исключения, содержимое файлов, ключи и абсолютные пути не публикуются.
- Хеш вычисляется после чтения файла в основном цикле, без двойного чтения при сканировании. Файл получает `indexed` только после успешной записи векторов; после ошибки LanceDB повторный запуск не пропускает его по уже сохранённому хешу.
- На проверке настоящей LanceDB обнаружен и исправлен связанный дефект фильтров: camelCase-поля `fileId`/`projectId` экранируются обратными кавычками. Двойные кавычки не сопоставляли строки, оставляя дубликаты и старые векторы после очистки или изменения файла на пустой.
- Добавлены регрессии пустого файла, пробельных окон, изменения файла на пустой, продолжения после локальной ошибки, возобновления и безопасной диагностики. Рабочий индекс не очищался и повторная индексация пользовательского проекта не запускалась.

**Проверки:**
- Backend: 14 suites, 162 теста — PASS; TypeScript backend/frontend и `git diff --check` — PASS.
- Изолированная интеграция с настоящей LanceDB и SQLite в памяти — PASS: пустой/пробельный файл не отправляется в embeddings, следующий файл индексируется без дубликатов, изменение содержимого на пустое удаляет старые чанки из обоих хранилищ, очистка векторов проекта работает.
- Провайдер в интеграции заменён синтетическим `fetch`; сетевых и платных запросов не было. Отчёт: `reports/e2e/indexing-empty-regression.json`. Полная повторная индексация Knowledge-Journey не проверялась.

### 2026-11-07 — Backend-конфигурация, сброс устаревших индексов и компактный вход

**Область:** Architecture | Backend | Frontend | Infra | QA | Documentation

**Что изменилось:**
- Пользователь перенёс конфигурацию и образец в `apps/backend/.env` и `apps/backend/.env.example`. Код и документация используют эти пути независимо от cwd; корневой `.env` не используется. Обновлены PowerShell-инструкции и Docker bind mount `./apps/backend/.env:/app/apps/backend/.env`. Защищённое содержимое файлов не выводилось.
- Зафиксированы API и поведение admin-раздела «Индексы»: fingerprint `{baseUrl,embeddingModel}`, явный общий сброс LanceDB/SQLite индексов, сохранение проектов и истории, HTTP 409 при активной индексации и требование переиндексации.
- Реализованы `IndexLifecycleService`, SQLite metadata fingerprint и process-local leases. Устаревшие индексы, включая legacy и смену модели с той же размерностью, блокируют index/search до явного сброса. Durable-маркер незавершённого сброса не позволяет использовать частично очищенные индексы после ошибки или перезапуска.
- Реализованы двухшаговое подтверждение/отмена сброса, очистка устаревших UI-ссылок и уменьшенная на 20% высота полей логина и пароля. Остальные поля приложения не изменены.
- После сброса проекты переходят в `idle` с нулевым прогрессом; проекты и история чатов сохраняются. Пользовательские индексы при разработке не очищались.
- Добавлен бесплатный maintenance E2E-runner для проверки подтверждения, очистки только изолированного стенда, сохранности истории и размеров полей. Vite загружает только `VITE_*`, backend-секреты не используются frontend-конфигурацией.

**Проверки:**
- Backend TypeScript и Jest: успешно (13 suites, 142 теста). Frontend TypeScript и Vitest: успешно (41 тест).
- Браузерная проверка высоты: логин и пароль `32.796875 px` вместо `41 px`, отношение `0.799924` — уменьшение на 20%.
- Maintenance E2E после переноса — 12 PASS, 1 SKIP (очистка уже отображённых ссылок без предварительного платного поиска). Проверены загрузка backend-конфигурации и вход, состояние legacy-индекса, отмена, валидация и авторизация сброса, подтверждённая очистка, `idle` после reload и сохранность настройки ключа после restart.

**Результат:**
- 11 E2E-сценариев прошли в headless Microsoft Edge: главная форма, модальный диалог/Escape, неверный и правильный вход, сохранение ключа, logout/revocation, rate limit, перезапуск и сохранность ключа, запрет секретных сниппетов/traversal, индексация, поиск/Monaco, чат.

- Backend: 124 теста / 12 suites PASS. Frontend: 35 тестов / 2 files PASS. TypeScript backend/frontend — PASS.
- Машиночитаемый отчёт без секретов: `reports/e2e/latest.json`.
- Не проверялись production/Docker, другие браузеры, системный диалог выбора каталога и часовой таймаут сессии в реальном времени.

### 2026-11-07 — Администраторская настройка OpenAI-compatible LLM и актуализация документации

**Область:** Architecture | Backend | Frontend | Infra | Documentation

**Что изменилось:**
- `LlmService` заменяет provider-specific `OpenRouterService`; настроен OpenAI-compatible API: `LLM_BASE_URL=https://polza.ai/api/v1`, `LLM_CHAT_MODEL=openai/gpt-4.1`, `LLM_EMBEDDING_MODEL=perplexity/pplx-embed-v1-4b`; ключ `LLM_API_KEY` задаётся администратором.
- Добавлены администраторские credentials из корневого `.env` и отдельная панель «Настройка API»; API key защищён bearer-аутентификацией, не возвращается клиенту и записывается в `.env` до обновления runtime-памяти. Для обычной файловой системы предусмотрена атомарная замена, а Docker single-file bind mount использует backup/restore fallback без гарантии абсолютной атомарности.
- Согласованы контракты status/login/logout/API-key, временная авторизация, ограничения brute force и отсутствие хранения credentials в browser storage.
- Обновлена конфигурация для root `.env`, исключение секретов из Git/Docker image и Docker bind mount `.env` в backend `/app/.env`.
- Закрыто чтение секретов через endpoint сниппетов: проверяются имена файлов и канонические пути, запрещены обходы через соседние директории и символьные ссылки, а также чтение временных копий конфигурации.
- Несовместимая размерность векторов обнаруживается до изменения индекса; ошибки фоновой индексации переводят проект в состояние `failed` и передаются через статус/SSE, не оставляя необработанных Promise rejection.
- Обновлены `README.md` и `tz-ai-rag-code-agent.md`: запуск и проверки PowerShell, production security, очистка всех проектных индексов при смене embedding-модели и осторожность с `npm run clean:data`.

**Проверки:**
- TypeScript `--noEmit` для backend, frontend и shared — успешно.
- Изолированный Nest HTTP smoke без реальной БД и `.env` подтвердил вход, защищённое сохранение, выход, отказ без авторизации и удаление старого публичного маршрута.
- Полные Jest/Vitest-наборы не выполнены из-за проблем установленного тестового окружения и отсутствующих Windows-зависимостей; новые unit/API-тесты добавлены. Production-сборка и запросы к реальному LLM не проверялись.
